## Operator rulings

- **R1** (2026-11-27): Operator distinguished trigger failure from background runtime failure — keep synchronous `spawn()` failures failing loud and rolling back even when `background: true`; accept only the UTF-8 `setEncoding('utf8')` fix and unifying duplicated logging.
- **R2** (2026-11-27): Operator accepted settling setup completion on `exit` (immediate release on exit code 0, bounded 50ms pipe-drain window on non-zero/signal exit) with a regression test for open-pipe descendants.
- **R3** (2026-11-27): Operator accepted adding optional `signal?: AbortSignal` to `AdminInvokerOptions`, aborting pending sockets in `runDreamuxMcp`'s `finally`, and adding end-to-end `runDreamuxMcp` tests covering >10s toolcall, `describe` timeout, and stdin-close socket release.
- **R4** (2026-11-27): Operator accepted deleting dead `WorktreeManagerOptions.platform` and unused `ResolvedWorktreeSetup` export, moving `readWorktreeSetup` before directory creation, extracting shared private `removeRegisteredWorktree(repo, path, force)` while keeping unconditional rollback on foreground setup failure regardless of `cleanup: 'keep'`, and adding branch-preservation and reopen-ordering assertions.
- **R5** (2026-11-27): Operator confirmed the trust boundary (no extra sandbox; `.dreamux-worktree.json` runs under the Dreamux host user on trusted local repositories, documented in KB/product catalog) and keeping `pipe` stdio for background scripts so failure logs retain `output_tail` (accepting daemon-restart termination as a documented limitation).
